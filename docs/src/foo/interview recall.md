## iframe 优缺点
###  优点
1. **样式隔离**：样式、js隔离，每个 iframe 中的样式只影响自己的内容，而不会影响其他 iframe 或外部页面的样式。
2. **封装性**：作为一个独立的容器，`iframe` 可以很好地封装应用程序的不同部分，使得它们可以被独立开发、测试和维护。
3. **可重用性**：单个 iframe 中的内容可以被嵌入到多个页面中，提高了代码和资源的复用性。
### 缺点
1. **调试和维护**：由于 iframe 中的内容是独立的，调试和维护可能会更加困难，特别是当需要在不同的 iframe 之间协调时
2. 跨域通信的问题，违反浏览器的安全策略，需要适配不同的浏览器
###  应用场景
 1. 单点登录
 2. 广告
 3. 微前端-无界

## 跨域
跨域是指一个网页的脚本试图访问另一个不同域名、协议或端口的资源时，被浏览器的同源策略所阻止。
解决方案：
1. JSONP：服务器返回一个包含回调函数名和数据的 JavaScript 代码段，客户端通过`<script>`标签加载该代码段并执行回调函数来获取数据。
2. CORS：服务器在响应中添加特定的 HTTP 头信息。
3. 代理： nginx、 本地dev-server
## cookie localStorage sessionStorage 区别
| 特性       | Cookie                          | LocalStorage             | SessionStorage        |
| -------- | ------------------------------- | ------------------------ | --------------------- |
| **存储位置** | 存储在用户浏览器                        | 存储在用户浏览器，不随请求发送到服务器      | 存储在用户浏览器，与会话相关联       |
| **存储大小** | 约 4KB                           | 5MB 到 10MB（依浏览器而异）       | 与 LocalStorage 类似     |
| **有效期**  | 可设置有效期，或会话 Cookie（仅在会话期间有效）     | 数据永久存储，直到用户删除            | 仅在当前会话有效，关闭浏览器后数据被删除  |
| **应用场景** | 存储登录凭证、会话跟踪、用户偏好设置              | 存储跨页面或会话的数据，如用户偏好、已读文章标记 | 存储当前会话的数据，如购物车内容、表单数据 |
| **安全性**  | 可能被截获，                          | 存储在客户端，较为安全              | 存储在客户端，较为安全           |
| **访问权限** | 可通过服务器端脚本和客户端脚本（如 JavaScript）访问 | 仅通过客户端脚本访问               | 仅通过客户端脚本访问            |
| 备注       | http-only                       | 监听事件                     |                       |

### type vs interface区别
| 特性                      | `type`                                                      | `interface`                                                              |
| ----------------------- | ----------------------------------------------------------- | ------------------------------------------------------------------------ |
| 定义方式                    | `type MyType = { ... }`                                     | `interface MyInterface { ... }`                                          |
| 合并（Declaration Merging） | 不支持合并。声明相同名称的 `type` 会导致错误。                                 | 支持合并。多个同名的 `interface` 会被自动合并。                                           |
| 继承                      | 通过交叉类型继承：`type NewType = OldType & AnotherType;`            | 通过 `extends` 关键字继承：`interface NewInterface extends OldInterface { ... }` |
| 能否定义原始类型                | 可以定义原始类型，如联合类型、交叉类型等：`type A = string \| number;            | 不支持。只能定义结构类型。                                                            |
| 表达式支持                   | 可以使用映射类型、条件类型等：`type Mapped<T> = { [K in keyof T]: T[K]; }` | 不支持。只能定义固定结构。                                                            |
| 实现                      | 不能实现 `type`。它们主要用于描述类型。                                     | 可以通过 `implements` 实现 `interface`。                                        |
| 类型别名                    | `type` 可以用作类型别名。                                            | `interface` 不用于类型别名，但可以用作类型定义。                                           |
| 可选属性                    | 支持可选属性。                                                     | 支持可选属性。                                                                  |
### 实现 Pick 、Partial

```typescript
type Pick<T, K extends keyof T> = {
  [P in K]: T[P];
};
type Partial<T> = {
  [P in keyof T]?: T[P];
};
```
